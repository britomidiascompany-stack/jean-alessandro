Guia de instalação
Google Tag Manager · Vercel

Instalar o GTM e ligar o servidor (Stape) no seu site na Vercel

Dois processos, um depois do outro: colar o snippet do GTM no código do projeto e, em seguida, apontar o subdomínio do container server-side pelo DNS.

Tempo estimado: 10–15 min + até 72h de DNS
Nível: iniciante
Contêiner de exemplo: GTM-KFKMT6BZ
1 Instalar o snippet no código 2 Apontar o subdomínio do servidor
01
Parte 1

Instalar o snippet no código do projeto

O de sempre: os dois blocos de código do GTM entram direto no projeto e sobem junto com o próximo deploy.

Antes de começar

O que você precisa ter em mãos

  • O ID do seu contêiner GTM — formato GTM-XXXXXXX, visível na tela de instalação do Tag Manager (usamos GTM-KFKMT6BZ como exemplo neste guia).
  • Acesso ao repositório do projeto (GitHub, GitLab ou Bitbucket) conectado à Vercel, com permissão para dar push.
  • Saber qual tipo de projeto está publicado — Next.js, ou HTML/Vite/React puro. Se não souber, veja o arquivo package.json na raiz do repositório.
O snippet abaixo veio direto da tela "Instalar o Google Tag Manager" do seu contêiner. Não precisa copiar de outro lugar — os dois blocos de código a seguir já usam exatamente esse conteúdo.
Passo 1 de 3

Cole o snippet no código do projeto

O GTM sempre exige dois blocos: um no <head> (o mais alto possível) e outro logo após a abertura do <body>. Onde colar cada um muda de acordo com o tipo de projeto — escolha o seu abaixo.

app/layout.tsx (o layout raiz do projeto — não um layout de rota específica)
app/layout.tsx

  return (

      <head>
        {/* Google Tag Manager */}

          dangerouslySetInnerHTML={{
            __html: `(function(w,d,s,l,i){w[l]=w[l]||[];w[l].push({'gtm.start':

              'https://www.googletagmanager.com/gtm.js?id='+i+dl;f.parentNode.insertBefore(j,f);
              })(window,document,'script','dataLayer','GTM-KFKMT6BZ');`,
          }}
        />
      </head>
      <body>
        {/* Google Tag Manager (noscript) */}
        <noscript>
          <iframe
            src="https://www.googletagmanager.com/ns.html?id=GTM-KFKMT6BZ"
            height={0} width={0}
            style={{ display: 'none', visibility: 'hidden' }}
          />
        </noscript>
        {children}
      </body>
    </html>
  );
}
No App Router, isso precisa estar no layout raiz (app/layout.tsx). Se colar em um layout de subpasta, o GTM só carrega naquela seção do site.

2

Suba a alteração para o Git

A Vercel republica sozinha assim que detecta um novo commit na branch de produção (normalmente main).

terminal
# na raiz do projeto
git add .
git commit -m "Instala Google Tag Manager"
git push
Acompanhe o deploy em vercel.com/dashboard → o projeto → aba Deployments. Quando o status virar Ready, o site já está com o GTM ativo.
Passo 3 de 3

Verifique se está funcionando

Abra a versão publicada em produção (não localhost) e confira por um destes dois caminhos.

A

Modo Preview do GTM

No Tag Manager, clique em Visualizar, cole a URL do site publicado e abra. Deve aparecer o painel Connected do Tag Assistant no rodapé da página.

B

DevTools do navegador

Abra o site → F12 → aba Network → filtre por gtm. Deve aparecer uma chamada para googletagmanager.com/gtm.js com status 200.

Se algo não funcionar

Problemas comuns

O GTM aparece no Preview mas não no site publicado

O push provavelmente foi para uma branch diferente da que a Vercel usa como Production. Confira em vercel.com/dashboard → o projeto → Settings → Git qual branch está marcada como produção.

Não aparece nenhuma chamada para googletagmanager.com

Dê um refresh forçado (Cmd/Ctrl + Shift + R) para ignorar cache do navegador.

Confirme que o snippet foi mesmo salvo no arquivo certo e que o deploy mais recente terminou com status Ready.

Bloqueadores de anúncio e extensões de privacidade podem esconder a chamada — teste em uma aba anônima sem extensões.

O GTM parece estar disparando duas vezes

Sinal de que o snippet foi colado em mais de um lugar — por exemplo no layout raiz e em um layout de rota específica. Deixe o bloco em um único arquivo, o mais alto possível na árvore do projeto.

Estou em Next.js App Router e não sei onde fica o <head>

O App Router não tem um arquivo <head> separado — o layout raiz (app/layout.tsx) já retorna a tag <html> inteira, então o <head> é escrito diretamente dentro dele, como no exemplo do Passo 1.

02
Parte 2

Apontar o subdomínio do servidor (Stape)

Depois do snippet instalado, o container server-side precisa de um subdomínio próprio (ex.: gtm.seudominio.com) para rodar como first-party. Isso é feito adicionando um registro de DNS, fora do código — não tem deploy aqui.

Antes de começar

De onde vêm esses dados

A Stape (ou a tela de configuração do seu container server-side) mostra uma tabela como a abaixo, com o subdomínio sugerido e o registro exato para criar. Os valores mudam por projeto — o exemplo usa os do container fda-lotezero.

TypeHostValue
CNAME gtm.fda-lotezero.vercel.app saf.stape.io
1

Adicione o registro CNAME no DNS do domínio

Onde exatamente depende de quem gerencia o DNS do domínio do projeto:

  • DNS gerenciado pela Vercel — Vercel → o projeto → Settings → Domains → o domínio → opção de gerenciar registros de DNS. Adicione Host e Value exatamente como na tabela.
  • Cloudflare — aba DNS → Records do domínio, adicione o CNAME e deixe o Proxy status desligado (nuvem cinza — "DNS only").
  • Outro provedor (Registro.br, GoDaddy, etc.) — mesma lógica: tipo CNAME, Host = subdomínio sugerido, Value = destino da tabela. Se houver campo TTL, deixe no padrão.
Ação necessária Se o domínio estiver atrás do Cloudflare (ou similar), o Proxy status precisa ficar OFF nesse registro — com o proxy ligado, a verificação nunca conclui porque o CNAME some por trás do IP do Cloudflare.
2

Aguarde a verificação

A propagação do DNS mais a verificação automática podem levar até 72 horas — na prática costuma ser bem mais rápido. Nenhuma ação sua é necessária nesse meio-tempo.

Verificação final

Confirme que o subdomínio ficou ativo

A

No painel da Stape / GTM

Volte na tela onde pegou a tabela de DNS. O aviso de "Actions required" desaparece e o subdomínio passa a aparecer como verificado/conectado.

B

Testando o CNAME direto

No terminal, rode dig gtm.seudominio.com CNAME (ou nslookup no Windows) e confirme que a resposta aponta para o valor da tabela.

Se algo não funcionar

Problemas comuns

Já se passaram 72h e ainda aparece "Actions required"

Confira se o Host foi digitado exatamente como na tabela (sem espaços, sem repetir o domínio duas vezes — alguns provedores já completam o domínio base sozinhos, então às vezes o campo Host é só a primeira parte, ex.: gtm).

Se o domínio estiver no Cloudflare, confirme que o Proxy status está mesmo desligado (nuvem cinza, não laranja).

Não sei quem gerencia o DNS do domínio

Rode whois seudominio.com ou verifique em qual registrador o domínio foi comprado — os nameservers listados lá indicam onde os registros precisam ser adicionados (podem ser da Vercel, do Cloudflare, ou do próprio registrador).

O site usa apenas o domínio padrão *.vercel.app, não um domínio próprio

Nesse caso vale confirmar com quem configurou o container server-side qual domínio de fato foi usado para o subdomínio sugerido — normalmente o server-side tagging é configurado sobre um domínio próprio do projeto, não sobre o domínio automático da Vercel.
